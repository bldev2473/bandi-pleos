# 반디 차량 앱 디자인 시스템

플레오스 공모전 차량 앱(`pleos-app`)이 따르는 기준이다.
반디의 데이터 출처인 트래블젠 웹앱(travelgen.kr, 저장소의 `app/`)의 디자인을 기준으로 삼는다. 데이터와 화면이 한 흐름으로 이어지게 하기 위해서다.

웹과 다른 점은 두 가지뿐이다. 차량 화면은 멀리서, 짧게, 햇빛 아래에서 읽히므로 명암비가 모자란 웹 조합 두 개를 바꿨다(아래 "웹과 다른 점").

## 근거

2026-11-15에 운영 사이트의 축제 목록(`/ko/events`)과 축제 상세(`/ko/events/4065756`)를 열어 계산된 스타일을 읽었다.

| 항목 | 웹앱에서 읽은 값 | 출처 |
|---|---|---|
| 색 토큰 | `--tone-*` 9개 | `app/app/globals.css` |
| 글꼴 | Noto Sans KR | `--font-body` |
| 카드 | 흰 바탕, 1px `ink/10` 테두리, `shadow-sm`, 모서리 16px(`rounded-2xl`) 또는 24px(`rounded-3xl`) | 상세 화면의 정보 카드, 큰 사진 |
| 주 버튼 | `bg-moss` 알약(`rounded-full`), 누르면 `river` | `LandingPage.tsx`의 `landing-hero-cta` |
| 보조 버튼 | 흰 알약, 1px `ink/15` 테두리 | 상세 화면의 "목록으로" |
| 선택 상태 | `moss/15` 바탕 + `moss` 글씨, 모서리 12px | 왼쪽 메뉴의 현재 항목 |
| 정보 줄 | 회색 칸(`clay`) 안 아이콘 + `slate` 이름 + `ink` 값 | 상세 화면 "정보" 카드 |
| 큰 사진 | 모서리 24px, 아래쪽 어두운 그라데이션 위에 흰 제목과 주소 | 상세 화면 머리 |
| 아이콘 | lucide 0.577.0, 선 굵기 2 | `package.json`, 화면의 `svg.lucide` |

사용 빈도(`app/components`, `app/app`의 `.tsx`): `bg-moss` 77회, `text-moss` 151회, `bg-ink` 8회, `rounded-full` 370회, `rounded-2xl` 128회. 웹의 강조색은 검정이 아니라 민트(`moss`)다.

| `slate` | `#6b7280` | 보조 글자, 정보 이름 (흰 바탕 4.83:1) |

| `moss` | `#6ec2bf` | 브랜드 색. 주 버튼, 볼 수 있는 시간 구간, 선택 상태 |

| `line` | `#111111` 10% | 카드 테두리 |

|---|---|---|
| `moss-deep` | `#2f7f7c` | 흰 바탕 위 민트 계열 글자 (4.72:1) |

### 웹과 다른 점

| 웹 | 명암비 | 차량 앱 | 명암비 |
|---|---|---|---|
| `moss` 버튼 위 흰 글자 | 2.07 | `moss` 버튼 위 `ink` 글자 | 9.11 |
| 흰 바탕 위 `moss` 글자 | 2.07 | 흰 바탕 위 `moss-deep` 글자 | 4.72 |

`moss`는 면(버튼, 구간, 배지)으로만 쓰고 글자색으로 쓰지 않는다.

## 글자

기기의 한글 기본 글꼴(Noto Sans CJK)을 쓴다. 웹의 Noto Sans KR과 같은 글꼴이다.
웹처럼 제목은 굵게(700), 소제목은 600, 본문은 400으로 쓴다. 차량 화면이라 크기만 키운다.

| 역할 | 크기 | 굵기 | 쓰임 |
|---|---|---|---|
| 큰 숫자 | 120sp | 700 | 주행 중 도착 시각 |
| 화면 제목 | 44sp | 700 | 행사 이름, 상태 화면 제목 |
| 판단 문장 | 30sp | 600 | "오후 5시 9분에 도착해요." |
| 본문 | 22sp | 400 | 이유, 정보 값 |
| 보조 | 18sp | 400 | 주소, 정보 이름, 눈금 |

한글이 든 글자는 고정폭 글꼴로 쓰지 않는다(글자 사이가 벌어진다). JSON 같은 원문 기록만 예외이고, 그것도 debug 겹침 화면에서만 보인다.

## 모양

- 카드: 흰 바탕, 1dp `line` 테두리, 모서리 24dp. 그림자는 웹의 `shadow-sm` 정도(1dp)만 쓴다.
- 큰 사진: 모서리 24dp, 아래 절반에 검정 0→60% 그라데이션, 그 위에 흰 제목.
- 버튼: 알약 모양, 높이 88dp 이상(차량 터치 기준). 주 버튼은 한 화면에 하나.
- 아이콘 칸: `clay` 바탕, 모서리 14dp, 56dp.
- 배지: 알약 모양. 아래 "판정 배지"를 따른다.

## 판정 배지

| 판정 | 문구 | 바탕 | 글자 |
|---|---|---|---|
| `reachable` | 볼 수 있어요 | `moss` | `ink` |
| `needs_charging` | 충전하고 가면 볼 수 있어요 | `moss` 18% | `moss-deep` |
| `ends_before_arrival` | 도착 전에 끝나요 | `ember` | `ink` |
| `not_today` | 오늘은 열리지 않아요 | `ember` | `ink` |
| `time_unknown` | 운영 시각이 공지되지 않았어요 | `mist` | `slate` |

판단 문장의 색도 판정을 따른다. 볼 수 있으면 `ink`, 볼 수 없으면 `ember-deep`이다.

## 시간 띠

이 앱이 답하는 질문은 "지금 가면 볼 수 있나" 하나다. 그 답을 한 줄 그림으로 보여 준다.

- `clay` 바탕 띠 위에 운영 구간을 `moss`로 칠한다. 볼 수 없는 구간은 빗금이다.
- 지금은 위에 세로선, 도착은 아래에 원으로 찍는다. 도착이 구간 밖이면 원이 `ember`다.
- 추천, 도착 판단, 안내 중, 주차 후 화면이 같은 부품(`TimeStrip`)을 쓴다.
- 자동차: Fluent 3D Automobile(60dp)을 띠 위에 얹는다. 원본은 왼쪽을 보므로 좌우를 뒤집어 진행 방향을 보게 한다.
  - 추천·도착 판단(정차 중에 보는 화면): 화면이 열릴 때 한 번만 지금에서 도착까지 1.4초 동안 달리고 도착점에 멈춘다.
  - 안내 중(주행 중): 지금 자리에 둔다. 시간이 지나 자리가 바뀔 때만 0.8초 동안 옮긴다.
  - 반복하는 움직임은 쓰지 않는다. 운전 중 시선을 끌지 않기 위해서다.

## 그림과 아이콘

- 그림 자리(36dp 이상): Microsoft Fluent Emoji 3D(MIT). 커밋 `1ffb34c`의 256px PNG를 그대로 쓴다.
- 버튼과 정보 줄 안 아이콘: lucide 0.577.0(ISC). 웹과 같은 판이다. 원본 SVG를 VectorDrawable로 옮겼다.
- 라이선스 원문: `pleos-app/THIRD_PARTY_NOTICES.md`

## 편의정보 칩

웹 왼쪽 메뉴의 선택 상태와 같은 모양(`moss` 18% 바탕, `moss-deep` 글자, 모서리 14dp)에 뜻을 나타내는 lucide 아이콘을 붙인다. 있는 항목만 보여 준다.

| 항목 | 아이콘 | 데이터 |
|---|---|---|
| 유모차 | `baby` | `stroller` |
| 수유실 | `milk` | `nursing` |
| 화장실 | `toilet` | `restroom` |
| 휠체어 | `accessibility` | `barrierFree` |
| 반려동물 | `paw-print` | `pet` |
| 실내 | `umbrella` (비가 와도 괜찮다는 뜻) | `indoor` |

lucide 0.577.0에는 유모차 아이콘이 없어 `baby`를 쓴다. 함께 탄 사람처럼 고르는 칩은 아이콘 대신 선택 표시(`check`)를 붙인다.

## 사진

- 출처: 트래블젠 웹의 공개 API `GET https://travelgen.kr/api/events/{contentid}/images`. 웹 축제 상세의 "추가 이미지"와 같은 TourAPI `detailImage2` 원본이다. 대표 사진(`thumb`)을 맨 앞에 두고 같은 주소는 한 번만 쓴다. 받기 전이거나 실패하면 대표 사진 한 장만 쓴다.
- 원본은 수 MB라서 긴 변 1600px 안쪽으로 줄여 읽는다.
- **캐러셀**: 추천·도착 판단 화면의 큰 사진. 옆으로 넘기고, 오른쪽 위에 쪽 점과 "3 / 10"을 표시한다. 사진이 한 장이면 쪽 표시를 그리지 않는다.
- **썸네일**: 주차 후 화면 머리. 사진이 여러 장이면 오른쪽 아래에 `images` 아이콘과 "10장" 배지를 붙인다.
- **사진 상세**: 캐러셀이나 썸네일을 누르면 연다. `ink` 바탕 위에 사진을 자르지 않고 전체로 보여 준다. 옆으로 넘기기와 좌우 화살표(88dp, `chevron-left`·`chevron-right`), 아래 쪽 표시를 둔다. 왼쪽 위 "사진 닫기"(뒤로가기와 같은 자리, 어두운 바탕용 모양)와 안드로이드 뒤로가기 키로 닫는다.
- **운전 중**: 캐러셀 넘기기와 사진 상세 열기를 막는다. 사진 상세가 열린 채 기어가 P에서 바뀌면 닫는다.

## 뒤로가기

기준: 웹앱의 `components/navigation/BackToListButton.tsx`(축제 상세의 "축제/행사 목록으로" 버튼).

- 모양: 흰 알약, 1dp `ink/15` 테두리, lucide `arrow-left`, 글자를 붙인다. 차량 터치 기준으로 높이 72dp, 글자 24sp.
- 자리: 화면 왼쪽 위에 고정한다. 대기 화면에는 두지 않는다.
- 아래쪽 버튼 줄에는 앞으로 가는 행동(안내 시작, 다른 곳 보기)만 둔다. 뒤로가기와 겹치는 "닫기"를 두지 않는다.
- 안드로이드 뒤로가기 키도 같은 동작으로 연결한다.
- 주행 중에는 음성 조작이 먼저지만, 동승자가 누를 수 있도록 버튼은 남긴다.

| 화면 | 버튼 글자 | 누르면 |
|---|---|---|
| 추천, 도착 판단, 결과 없음 | 처음으로 | 대기 화면 |
| 안내 중, 귀갓길 | 처음으로 | 대기 화면 (내비 안내는 계속) |
| 도착, 주차 후 | 처음으로 | 대기 화면 |

뒤로가기는 내비 안내를 끝내지 않는다. NaviHelper 3.0.5의 `cancelRoute()`는 Pleos 내비 화면을 앞으로 띄우고, 안드로이드는 이 앱이 다시 앞으로 오는 것을 막는다(2026-11-15 에뮬레이터에서 확인). 그래서 뒤로가기가 앱을 빠져나가게 된다. 안내는 내비 화면의 안내 종료나 Gleo 음성으로 끝낸다. 운전 중 실수로 눌러도 안내가 끊기지 않는다는 이점도 있다.

## 화면 구성

- **정차 중(기어 P)**: 왼쪽에 큰 사진 카드, 오른쪽에 판단 문장, 시간 띠, 이유, 정보 줄, 버튼.
- **주행 중**: 도착 시각, 시간 띠, 한 줄 안내만 둔다. 버튼을 두지 않고 Gleo 음성으로 조작한다.
- **개발 정보**: Gleo 연동 기록, SDK 상태, 개발 도구는 debug 빌드에서만 오른쪽 위 렌치 버튼으로 연다. release 화면에는 나오지 않는다.

## 문구

- 말투는 존댓말 하나로 맞춘다. 사용자가 Gleo에게 하는 말(따옴표 안)만 반말이다.
- 같은 동작은 같은 이름을 쓴다: 안내 시작, 집으로 안내.
- 계산 결과 대신 시각을 그대로 말한다: "도착하면 마감까지 5시간 51분" 대신 "오후 5시 9분에 도착해요. 오후 11시까지 열려 있어요."
- 내부 말(검수, 후보, SDK 이름)을 화면에 쓰지 않는다.
- 원본 제목 앞의 연도("2026 ")는 표시할 때 뺀다.
